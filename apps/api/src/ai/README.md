# Forecast inference (CG-AI-04)

`forecast.ts` loads only `ml/forecasting/data/forecast_cg_ai_03c_model.json`, validates its pinned SHA-256/schema, resamples raw telemetry into 15-minute mean-power samples, and reproduces the Python Ridge Delta features and transform in Node. It returns the S4-C2 `ForecastRecord`; it does not persist or expose it over HTTP (CG-AI-05), and it never calls a GoodWe command.

CG-AI-05 wires this service to the existing Node clock. For online plants, the clock aggregates persisted energy samples into minute means over the last 26 hours (at most about 1,560 rows), then attempts one forecast per 15-minute input window. Only `AVAILABLE` forecasts are inserted into `commercial_forecasts`; `(plant_id, model_version, input_to)` is unique. `GET /commercial/plants/:plantId/forecast` only reads the latest row and never runs inference. Before the first available forecast it returns `{ forecast: null, availability: "UNAVAILABLE", unavailableReason: "FORECAST_NOT_GENERATED" }`. Expired rows are projected as unavailable with deterministic persistence fallback without modifying the stored record.

CG-DEC-01 evaluates an available forecast against the plant's persisted demand policy in the existing commercial repository. It accepts only the promoted model, a 60-minute horizon, valid future points and an input window no older than two 15-minute steps. The highest forecast point is `PREDICTED_ALERT` at the policy alert threshold (Aurora: 80%) or `PREDICTED_CRITICAL` at its critical threshold (Aurora: 90%). Critical blocks only new starts; alert is visible evidence and does not add a block. The S4-C2 `DemandDecisionEvidence` is persisted idempotently in `commercial_demand_decisions` by a correlation key scoped to plant, forecast and policy/thresholds. The energy decision response returns that evidence. Missing, expired, incompatible or stale forecasts leave the existing telemetry-based rule authoritative. Forecasts never issue `StartCharge`/`StopCharge`; reactive protection remains unchanged.

At least 96 consecutive complete quarter-hours are required. Raw telemetry is averaged over each completed quarter-hour; the still-open interval is discarded. Each bin needs at least 15 readings, edge coverage and no gap over 60 seconds. A result expires no later than 30 minutes after `inputTo`. Missing/invalid model, insufficient/gapped/stale input, or expired result is unavailable; if a current reading exists, `fallback` is a clearly separated persistence estimate, not an AI forecast. The risk threshold is the model's offline training benchmark threshold, not plant policy and not a control signal.

Training timestamps were naive wall-clock labels with unavailable source timezone. The API uses UTC fields from its ISO timestamps without conversion to reproduce the numeric calendar encoding; that does not establish calendar-semantic parity for Aurora. Training data remains `SIMULATED_COMPOSITE`. The prototype may apply the model only to simulated GoodWe telemetry and only to block new starts at the critical threshold; using this benchmark with physical equipment or real plant telemetry is not validated and remains prohibited pending representative data and policy review.

Focal checks: API tests cover Python/Node parity, coverage/fallback, route behavior, idempotence and PGlite restart persistence. The general `plantEnergySeries` endpoint remains capped at 3,600 rows; forecast aggregation uses a dedicated database query and does not expand that endpoint.
